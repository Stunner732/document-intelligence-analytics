# Synthetic operational extension specification

## Purpose and boundary

The BPI Challenge 2017 log supplies real workflow events but omits several fields needed for the document-operations scenario. The future canonical dataset will add deterministic **synthetic labels** at the loan-application-case grain. They model a fictional operations layer; they are not attributes, performance outcomes, or business findings of the source institution.

The raw event log remains unchanged. Each synthetic field will be tagged as `synthetic` in lineage metadata and generated by a versioned, seed-controlled transformation in a later phase.

| Field | Method | Status |
| --- | --- | --- |
| `document_id` | Application trace identifier | Source-derived |
| `document_type`, `page_count`, `branch`, `operator_team`, `priority`, `region`, `quality_score` | Stable fixed-seed labels/values derived from document ID or anonymized resource | Synthetic |
| `received_timestamp`, `processing_start_timestamp`, `processing_end_timestamp` | Source-event timestamp rules | Derived |
| `status`, `rejection_flag`, `processing_stage` | Source-event outcome/activity mapping | Derived |
| `error_flag` | Documented rework/incomplete-event proxy | Synthetic proxy |
| `sla_target_hours` | Synthetic target from synthetic priority/type | Synthetic |
| `channel` | Submission-event sequence proxy | Derived proxy |
| `document_category` | `LoanGoal` | Source-derived |
| `customer` | Not created | Not available |

## Guardrails

- Synthetic branches, teams, priorities, SLA targets, page counts, error proxies, regions, and quality scores are not source facts and will be visibly labelled in datasets, charts, API responses, and documentation.
- A source-derived outcome must not be relabelled as a source error.
- No customer identity will be inferred or synthesized from the anonymized event log.
- All mapping rules, random seed, and fallback rules must be recorded before a processed dataset is generated.
- Phase 3 will retain rejected, invalid, and ambiguous records in a quarantine/report flow rather than silently discarding them.
